## Proposed claims

- pending `c1` (announcement): The operator talks with Gwen — by voice on the rig and by text at gwen.culture.dev behind Cloudflare Access — and she remembers their Pocket recordings and culture-rules' daily newspaper: culture-rules enqueues distilled facts through an embodiment-owned memory ingest verb, the daemon is their single writer, recall finds them semantically through gemma2-embed, every recalled fact is cited by its source, and pocketchat can retire
- pending `c2` (requirement): `embodiment memory ingest --file <ndjson>` and `memory forget --source pocket --source-id <id>` validate the whole batch, then enqueue it atomically (temp + rename) into a 0700 inbox under the daemon's state dir; they never write the store, are dry-run unless `--apply`, and take `--json`
- pending `c3` (requirement): the running daemon is the only consumer of the inbox: it drains batches in filename order, one record write at a time so no write holds the store lock across a batch, and moves each batch to done/ or failed/ with a safe reason; batches queued while the daemon is down apply on the next start
- pending `c4` (assumption): a concurrent ingest write competes with turn recall for `_STORE_LOCK`; recall's 0.25 s deadline (memory.py:305, app.py:697) returns no records on a miss, so the drain must yield between records or it silently costs turns their memory
- pending `c5` (requirement): ingested records land in the one shared private ingest scope of c39, which recall reads alongside `gwen`; visibility private, the scope and `added_by: culture-rules` are stamped by the verb and never taken from the file
- pending `c6` (requirement): record ids rendered in a prompt or forgotten by the tool use a charset the funnel accepts; either the wire id `pocket:<rec>:<kind>:<n>` is mapped to a charset-safe stored id or the header charset is widened, with the fuzz test re-run either way
- pending `c7` (requirement): a record carrying `supersedes` hides the record it replaces before the batch is reported done — the daemon flips the old record's lifecycle itself; nothing relies on a later `eidetic sweep`
- pending `c8` (assumption): the files backend deletes an older record in the same scope file whose text hash matches a new id (files.py:53-58), so two recordings that distil to identical text collapse; ingest must make text distinct (e.g. provenance in the text) or accept and report the collapse
- pending `c9` (requirement): `memory forget --source pocket --source-id <rid>` archives every record whose metadata.recording_id matches by enumerating the scope (not by ranked recall); a per-id forget exists for the surplus ids a re-distil leaves behind
- pending `c10` (requirement): a recalled recording fact renders through the single `render_recalled` funnel with its provenance (recording title, date, mm:ss) as neutralised, quoted data; the fuzz generator and the one-sanitiser AST test are extended to every newly rendered field
- pending `c11` (boundary): recalled recording facts are data only: no code path turns recalled text into a tool call, recordings are unreachable by the `forget` tool, and a hostile imperative inside an ingested record provably causes no tool call (test)
- pending `c12` (non_goal): embodiment makes no model calls and no content decisions on ingest — distillation, id minting, `supersedes`, and what to forget are culture-rules' (projection rule, #94 comment 6351646938)
- pending `c13` (non_goal): ingested records are never pushed into an active session's prompt; they become recallable memory only (#94 refinement 6351576099; #90)
- pending `c14` (requirement): the ingest verbs run correctly under culture-rules' runner: an absolute argv, no stdin, a throwaway cwd and an env of only PATH and LANG — so the state dir is given by flag (`--state-dir`) and `--file` takes an absolute path; exit 0 means success
- pending `c15` (requirement): the verbs are genuinely idempotent: re-enqueuing the same file twice changes nothing in the store, because `machine.command` has no idempotency key and the engine retries only steps declared idempotent
- pending `c16` (assumption): pocketsync will emit `pocketsync.recording.landed`, `.deleted` and `.merged` as outbound events; today it emits only `.enriched` and `.reclassified`, and deletes/merges are inbound webhooks that emit nothing — so until it does, forget-on-delete has no trigger
- pending `c17` (requirement): `memory` is a CLI noun with `ingest`, `forget` and `overview` leaves on the nested-subparser precedent, each with an explain-catalog entry, so the introspection tests and `teken cli doctor --strict` stay green
- pending `c18` (requirement): a text chat with Gwen: a new guarded POST route and Controls callable that runs a text turn through the daemon's existing turn path (`run_turn`), bounded so a slow model call is not a control-timeout 503, and a chat view in the dashboard
- pending `c19` (requirement): a cited, owned copy of pocketsync's stdlib Access verifier backs the guard's `assertion_verifier` seam, configured by an all-or-nothing `EMBODIMENT_ACCESS_TEAM_DOMAIN` + `EMBODIMENT_ACCESS_AUD` pair; an unavailable JWKS refuses with 503, every other failure with 401/403; with the pair unset behaviour is byte-identical to today
- pending `c20` (before_state): today the guard checks the install secret before the Access assertion (guard.py:541-551) and the default verifier refuses every token, so the public Host is unreachable and an Access-authenticated browser would still need the install secret
- pending `c21` (requirement): chat answers that use recording memory show provenance (title, date, timestamp) rendered with textContent only and dir=auto, reusing pocketsync's post-retrieval pipeline (source fencing, [k] citation validation) over Gwen's lexical recall
- pending `c22` (requirement): the README not-yet entry for Cloudflare Access, the explain root, CLAUDE.md and the tunnel verb's default hostname move to the shipped state for gwen.culture.dev, with `tests/test_release_docs.py` updated
- pending `c23` (non_goal): pocketchat parity beyond chat — a recordings list with filters, a transcript reader with the cited passage highlighted, an action-items list — and Gwen's own full-transcript lookup (pocketsync MCP / read verbs, a first tool beyond memory under #89) are not part of this cycle
