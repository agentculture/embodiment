# Library live acceptance - 2026-10-24

Plan task `t15` of `gwen-is-pocketchat-transcripts-as-knowledge`. Aggregates
only: no document text, no question text, no answer text. The question sets
were written by the gateway's `worker` role before each run, hashed, and kept
outside the repository because they derive from real documents.

## Setup

- Daemon: branch `feat/gwen-is-pocketchat` (0.18.0), a scratch state directory
  (synthetic memory store), library configured with
  `EMBODIMENT_LIBRARY_URL=http://127.0.0.1:8780` and Gwen's own GET-only key.
- Library: xteink's live instance (today's instance of culture-library). At
  the first run it held 17 items (13 daily newspapers, 3 documents, 1 book);
  during the session culture-rules pushed 33 recording transcripts and one
  more newspaper, so the second run saw 51 items, 50 indexed (the book is not
  opted in).
- Gateway roles re-probed first: `stt` (local), `senses`, `tts`,
  `gemma2-embed` and `worker` all ready.
- Similarity threshold: `0.715`, memory's value, **provisional and not
  calibrated on library text** (plan risk r6).

## Two defects found live, fixed before measuring

1. **Every real item failed extraction** (`extract_failed`, 16 of 16): the
   daemon handed `epub.extract` to the sync, which calls `extract(data)`, but
   the function required a `limits` keyword. Every unit test used a fake
   extractor, so the seam was never exercised. Fixed in `d08ee5b` with a test
   that calls the daemon's own default extractor the way the sync does (lapse
   l11).
2. **`skipped_books` counted refused items, not books.** Split into
   `skipped_books` and `skipped_refused`.

later.

## Does Gwen use the library in a full typed turn?

| --- | --- | --- | --- | --- | --- |
| As planned (t13) | 0 / 6 | 0 | 0 | 0 | 0 |
| With deviation d1 | 3 / 6 | 3 / 3 | 15 | 15 / 15 | 0 / 6 |

As built, Gwen never called `search_library`, although `senses` called it 2 of
2 times when prompted directly with the tool. Deviation **d1** (operator
approved) added one fixed prompt line to typed turns with a library, a
sharper tool description, and `status.library.tool_calls`. Every library
citation resolved, but **no reply text carried an `[n]` marker**, so the page
shows the citations in its sources list (each opens the reader at its
passage) and never as inline markers in the answer.

## Transcripts carry no timing

The 33 transcript EPUBs contain headings, lists and paragraphs only: 0
timestamp-shaped tokens, 0 speaker lines, 0 `data-*` attributes across three
sampled items, and Gwen's extractor found 0 timed and 0 speaker passages in
six. Pocketchat's tape and jump-to-moment therefore cannot work for them;
citations open the reader at the cited passage (the untimed branch t8 built).

## Library client requests

`status.library.gets` counts every request the client issued: 18 in the first
session's sync and searches. Non-GET requests: **0 by construction**. The
client module contains no write method, pinned by an AST test in CI. No
separate live counter of non-GET requests exists, because the client cannot
send one.

## What this does not show

- Retrieval quality on a realistic distractor pool, or with a calibrated
  threshold.
- Whether d1's prompt line generalises beyond these six questions (n = 6).
- Voice turns, which do not get the library tools this cycle (c39).
- Any value claim. The operator's stated aim is one place to talk with what
  he has read and recorded; this run measures retrieval and wiring, not that.
