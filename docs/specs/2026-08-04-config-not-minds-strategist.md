# config-not-minds strategist

> the strategist changes configuration, not minds: typed, gated, tested and revertible prompt/example/verification changes replace advisory directives; the worker is unaware of the strategist; senses relays the world to the embodiment and the inner state to the world; no default changes until the config-change arm is measured against the advisory arm and the ungoverned control
> instruction: add a strategist guard to tests/`test_governance.py` copied from the muse/drone templates (opt-in flag pinned False, env fails closed, AST single-bypass, and a TestTheseGuardsCanFail case), and gate any default flip on the ScopeBench re-run verdict

## Audience

- hosts that embed embodiment (colleague, the reachy family, greenhouse-style example apps) plus this repo's own example hosts and ScopeBench harnesses; the operator arms the strategist explicitly, and end operators keep experiencing one coherent teammate

## Before → After

- After: the strategist improves the rig by changing configuration in the background - the worker and senses seats simply operate under better tools, prompts, knowledge and permissions - and what the operator experiences is an assistant or companion they can and want to work with: a diverse mind entity

## Why it matters

- the advisory design puts a persuasion problem in the loop and the only matched control measured it buying nothing: 189.6 s and 3663 strategist tokens for zero applied directives and a materially identical answer, with 69.5% of session tokens buying restatement or nothing - configuration change replaces advice that can be ignored with inputs that are actually different

## Requirements

- the strategist's output unit becomes a typed configuration change - prompt change, code-example change, verification-rule change - each type with its own schema, its own gate and its own test, per issue #75; the 'gated and tested' clause carries the entire safety story because configuration authority is strictly stronger than directive authority
  - instruction: one typed change-unit dataclass per type, a per-type gate hook, and a per-type test module; an unknown or extra-keyed unit is refused whole
  - honesty: a change type without its own schema, its own gate and its own test does not ship - 'gated and tested' is verifiable per type, not a slogan on the tier
- ratchet prevention is a first-class requirement with its own pre-registered measurement condition: advice evaporates, configuration accumulates - successive changes each passing their gate can compound badly, and the failure already appeared in miniature in the advisory design when a one-off task instruction became a durable persisted constraint (live session §4.2, #66)
  - instruction: add a ratchet condition to the pre-registration (advisory design cannot get permanently worse; this one can) and a revert-to-baseline path exercised by test
  - honesty: compounding is detectable, not assumed away: successive gate-passing changes are re-evaluated against a fixed baseline so drift each individual gate misses still shows, and reverting to baseline is always possible
- every applied configuration change is revertible and its effect observable under C3: a subtly worse prompt is the most silent degradation available, so apply/rollback are recorded transitions and detection of degraded behaviour is part of the design, not an operator hope
  - instruction: emit config-change events (proposed/validated/applied/rejected/reverted) through the existing `scope_events` translation pattern; persist the applied-change ledger through the ScopePersistence port
  - honesty: no configuration change degrades silently: every apply and revert is a recorded transition, and the host can observe that behaviour changed because configuration changed (C3)
- value is measured before any default changes: a ScopeBench re-run with a config-change arm against the advisory arm against the ungoverned control, same seven-condition verdict rule plus a new ratchet condition and a new absent-cell reason; fixing #58 (`SCOPE_AUTHORITY` never states the `scope_id`-must-be-new rule) is a precondition for the advisory arm to be a fair comparator - 47 of 93 proposals refused as duplicates voided 32 of 36 cells of the layer control last time
  - instruction: pre-register before running; publish the result whichever way it comes back, defects included
  - honesty: the verdict rule is committed before any dial and one ABSENT condition forces INCONCLUSIVE, which leaves the shipped rig untouched - the same rule that kept the muse and the advisory strategist out of the reference rig

  - instruction: add TestStrategistShipsOptInAndOff to tests/`test_governance.py` on the drone-guard template; fix the CLAUDE.md sentence in the same PR

  - instruction: write the per-change-type verdict rule into the ScopeBench re-run pre-registration; record each type's verdict in docs/live-test-results/ with the run that decided it
  - honesty: the three-way verdict rule (allow ungated / gate / shut off) is committed per change type BEFORE any dial, and every change type's verdict is recorded beside the measurement that produced it - a verdict rule written after seeing results is not a gate
- the strategist's configuration surface is: the worker's tools, prompts, knowledge, and permissions (what it is allowed to do); and the senses seat's prompts, permissions, and basic knowledge
  - instruction: define one typed change-unit schema per target (worker tools / prompts / knowledge / permissions; senses prompts / permissions / knowledge), each with its own apply, revert and record path; reuse the FORBIDDEN-keys refuse-whole pattern for shape violations
  - honesty: every configuration change routes through host-owned configuration surfaces - the host's injected ToolExecutor and approval policy are never bypassed, and a change unit with an unknown shape is refused whole and recorded, never partially applied

  - instruction: the ScopeBench re-run and live session 2 grade the worker-as-actor cells explicitly; their verdict is what the promotion cites
  - honesty: the flag flips only in the same change that cites a docs/live-test-results/ verdict actually supporting the worker as acting loop; the t24 truncation lesson transfers to whichever seat acts (the worker's `finish_reason` is equally absent, #37)
- the worker may write the senses seat's knowledge - a designated, schema-distinct block of what composes senses' context (arguably part of the prompt, deliberately designated as its own surface) - but never senses' prompts; prompt authority over senses belongs to the strategist alone
  - instruction: model the senses knowledge block as its own change-unit target carrying an origin field; prompt targets accept strategist-originated units only; enforce by schema refusal plus a test that a worker-originated prompt write is refused whole
  - honesty: the designation is structural, not conventional: the knowledge block is a schema-distinct surface the worker writes through a defined seam, senses' prompt text is unreachable from any worker-writable surface, and a worker-originated write to a prompt-shaped target is a refused shape, recorded
- the worker-to-senses knowledge channel is attributed, because it is a path from the acting tier to the operator's ear: every knowledge-block entry carries origin attribution as a required field, and senses' framing states that knowledge entries are attributed claims - the #63 record shows senses relays what it is given and defers under pressure, so an unattributed channel would let a compromised or fabricating acting tier put words in the interaction tier's mouth anonymously (the config-design analogue of the t6/#55 surrender direction)
  - instruction: origin is a required field of the knowledge change-unit schema; senses framing for hosts includes the knowledge-attribution clause; test that an unattributed write is refused whole
  - honesty: a knowledge entry with no origin attribution is a refused shape, recorded; a fabricated or injected entry is traceable to its writer in the ledger; and the senses grounding clause covers the knowledge block explicitly (knowledge is attributed claims, not the seat's own perception)
- the config-change ledger schema is versioned and fail-closed against advisory-era persisted state: a host whose ScopePersistence payload holds an advisory directive chain gets a recorded refusal or ignore with a version hint - never a silent reinterpretation of old state under new semantics, never a crash into the host's main path
  - instruction: stamp a schema version into the persisted payload; refuse unknown or advisory-era versions with a recorded degradation naming the fix
  - honesty: a config-design host pointed at an advisory-era state file degrades visibly (one recorded degradation, actor continues unconfigured) - exercised by test with a real advisory-era payload fixture
- an operator-visible introspection surface reports each seat's current effective configuration with provenance - which change produced it, when, under which gate verdict - derived from the applied-change ledger (one source of truth, no parallel bookkeeping), so any operator-visible utterance can be traced to the configuration active when it was produced; this is the running-system capability introspection issue #75 itself names as missing, and it is also what makes a revert honest: revert restores configuration, not the world, and the record shows which config each past utterance rode
  - instruction: a host-callable report function (and a CLI verb later if warranted) rendering effective config per seat from the ledger; live session 2 uses it to audit the session
  - honesty: the introspection output is derived from the applied-change ledger and nothing else; a config state the ledger cannot explain is itself a recorded degradation (C3)
- config changes apply through propose -> verify -> apply: a change (prompt changes are the named instance) is first a proposal; a test suite verifies it against the affected seat; it applies only when that seat is available for testing, not in a run, and the suite passed - so the session continues mid-drive while no seat ever has its configuration changed under it mid-run
  - instruction: implement propose/verified/applied as distinct recorded states (extend c8's event kinds with 'verified'); the verifier runs the per-type test suite against the idle seat - the drone stage-smoke-save pattern at runtime; gate apply on seat-idle plus suite-pass
  - honesty: a seat that is mid-run never observes a config change: apply is atomic between runs for that seat, making the advisory design's constant-sha mechanism check per-seat (config constant within any single run, changes only between runs); a proposal whose suite fails is never applied and the failure is recorded, like a failed drone smoke
- the knowledge block rides eidetic - no parallel memory system: worker writes and strategist maintenance land as eidetic records in a designated scope, senses reads via recall, and the strategist/cortex maintains the store over time (consolidation, supersession, ageing decisions) - eidetic owns memory mechanics, embodiment owns when entries are written, recalled and revisited in the lived sequence (issue #2's split, applied)
  - instruction: model knowledge change-units as eidetic records in a designated scope per the scope+visibility convention (eidetic docs/contract.md); worker writes via remember, senses reads via recall, strategist maintenance uses eidetic's consolidation/supersession verbs; test that the knowledge path imports no store of its own
  - honesty: no second knowledge store drifts into existence: the knowledge block is eidetic records under a designated scope, c30's origin attribution rides eidetic's native provenance rather than a new invented field, and a knowledge write that bypasses eidetic is a refused shape

## Honesty conditions

- the shipped rig stays untouched until a pre-registered verdict supports promotion: the redesigned tier ships opt-in and off, an INCONCLUSIVE result leaves the rig as-is, and this time the rule is held by a real governance guard (`test_governance.py` currently has none for the strategist)
- provable, not asserted: the existing suite plus the AST import-closure test stay green unmodified, and an unarmed governor still forwards the host's objects by identity - the same three pins that hold today hold after the redesign
- no change of this frame touches colleague: every senses-half change lands either in embodiment's host-owned surfaces or as a filed colleague issue - checkable in the delivery record
- no configuration path can grant the strategist an ability the host has not itself wired: tools and permission changes select among host-offered capabilities, never mint new ones, and the host's approval policy sees every effective change
- the after-state is demonstrated end-to-end on a non-colleague host (issue #2's definition-of-done rule) and judged in live session 2 against a matched ungoverned control, not asserted from bench cells alone
- a host can wire the tier from documented seams alone - the #62/#58-class traps either ship fixed or are documented at the seam, so a correct-looking wiring cannot silently produce an incapable tier
- the motivating numbers stay cited as what they are - n=1 on one rig with one model pair, a report not a measurement - and are never inflated into 'proven worthless' any more than 'proven valuable'
- separation means the pre-registered margins under the committed verdict rule; a tie or an ABSENT cell reads INCONCLUSIVE and ships nothing - the same rule that kept the muse and the advisory strategist out of the rig

## Success signals

- the config-change arm separates from both the advisory arm and the ungoverned control under a pre-registered verdict rule that includes a ratchet condition - and in live testing the governed rig produces a measurably better session than the matched ungoverned control, instead of session 1's materially-identical-at-higher-cost result

## Non-goals

- no 'deterministic effect' claim ships in any doc or authority text: the change is deterministic, the effect is not - a rewritten prompt still routes through a model and the response remains a sample; the guarantee is about the input (the model's inputs are actually different), guarded now because `h3`/`d5` showed 'provably never executes' hardening into an overclaim
- 'diverse mind entity' is stated with C2 discipline: the diversity is architectural fact - cooperating roles across model families, always trace-visible - while the prompt-visible identity stays one teammate (Gwen); no affective claims, and any inner state relayed outward is a report of system state per the existing rule

## Decisions

- the target architecture is a three-tier loop: senses (relay between world and embodiment) - worker (the acting loop, narrower scope, writes code, unaware of the tier above) - cortex serving as strategist (background configuration changes). colleague exemplifies the two-tier senses-cortex loop; this frame builds the three-tier variant, so the cortex moves up from acting to configuring and the worker takes the acting seat
